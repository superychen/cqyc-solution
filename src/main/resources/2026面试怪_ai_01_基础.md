# ai基础知识相关

### 1、上下文窗口 context window
    定义：llm能一次性输入+输出的总token数
    1、如果是自部署模型，受模型训练长度、位置编码扩展方法和推理引擎配置影响
    2、超出窗口限制解决方案：01：截断--保留最近的对话  02：总结：用llm总结历史对话  03：滑动窗口--只保留最近N轮 04：向量检索---将历史存入向量库，按需检索 
        05：分层摘要--重要信息摘要+最近对话原文

### 2、减少幻觉的方法
    1、rag--基于检索内容回答 2、prompt约束--不要编造，不知道就说不知道 3、引用溯源--要求标注来源 4、外部校验--对实体、数字和引用做规则或工具验证。
    5、人工审核--高风险场景设置人工复核和拒答边界

### 3、llm为什么是随机模型, 同样的输入输出为什么会不一样？
    1、训练目的就是概率：学的就是下一个token可能会出现的概率。2、生成靠采样：解码从概率中选取token 3、知识是统计规律：模型学的是不确定规则。
    面试答：LLM 是概率生成模型，输出层是一个词表上的概率分布，解码时通过采样策略选 Token。所以同样输入可能输出不同——这是采样随机性导致的

    输入输出不一样：
    1、采样随机性：top-P/top-K/温度设置相关 2、浮点非确定性：GPU并行累加顺序差异 3、多轮上下文：多轮对话的情况下，模型想法不同 4、模型服务负载。
    面试答：在真实场景中，食安agent需要确定性时用T=0 + 固定的seed + 输出校验；需要多样性适当提高温度。需要可靠性时用多次采样投票

### 4、如何量化（检测）幻觉 与 偏见
    1、检测幻觉的话一般使用 01-引用溯源，要求模型给出引用/来源，02-忠诚度评估（faithfulnees）--在rag系统中使用RAGAS等框架检测回答是否忠于检索内容
        03-交叉验证--同一问题问多次或不同模型，对比一致性 04-事实核对，特殊敏感实体用外部工具验证。 05-不确定性探测--直接问模型有多确定。
    2、真实工程中一般第一道防线，必须带着溯源/引用。 第二道使用faithfulnees，定期抽样评估指标，监控幻觉率变化。 第三道在 高价值场景中使用交叉验证，或人工复核。
    
    对于偏见：
    1、模型在性别、种族、地域等方面不公平输出。原因就是在训练模型中的社会偏见，标注人员的主观偏好，采样策略导致分布偏移。
    2、缓解方案：01--数据平衡：增加少量人群样本  02--RLHF对齐：人类反馈强化学习  03--提示词工程：明确要求公平性 （重要） 04：后处理过滤：检测并修正偏正
    
    总结：幻觉和偏见是llm核心问题，我们项目中使用的是rag解决幻觉，基于知识库去回答，未找到时明确告知。偏见方面：我们在prompt中明确要求请公平对待所有充满歧视的回答。
        在后续如果是公司要搭建自己模型时，需要考虑在RLHF阶段强化这一点。
    

### 5、如何评估LLM的输出质量
    我们项目中用双层评估-自动指标RAGAS跑全量数据，人工抽样200条核心case。关键维度是忠实度（不能幻觉）和相关性（要答对问题）。每次模型迭代都要对比这些指标，确保没有退化。

### 6、长文本超出context window如何处理
    1、滑动窗口，截断。不推荐，滑动窗口可在实时对话时使用。2、摘要压缩，LLM递归摘要，可能失真，适用文档概览。3、RAG分块，切分+向量检索，最优，问答/检索时使用。
    4、长上下文模型：用128K窗口模型。
    lost in the middle问题：
    给一个LLM20K文档，关键信息在中间，LLM往往只关注开头和结尾，大海捞针失败。解决方案：方法1--将关键信息提取出来，放到开头和结尾。方法2--分段+多次查询。
    
    面试答：长文本处理首选RAG:切分+检索+生成。滑动窗口适合对话,但会丢失早期信息,我们用分层管理解决——最近3轮保留原文,历史做摘要。长上下文模型虽强但贵,128K窗口成本是8K的15倍,只在必要时用


### 7、如何LLM选型？质量/速度/成本怎么权衡？
    选型我的方法是 '任务复杂度×质量×成本'三维权衡： 先拿真实任务测量候选模型质量，再看单价和缓存算成本，最后按峰值需求定预算。工程上我会配模型路由--简单问题走小模型，复杂推理升级旗舰，再加
    prompt caching降输入成本。我们项目中现在就是qwen主力 +  deepseek备选。夜间批量任务挑低峰时段跑，成本这样能降低60%左右。


### 8、logits是什么？如何生成下一步token的？
    logits是模型对词表每个token的原始打分，经过softmax变成概率。生成时先算logits，再用采样策略（贪心/topK/top-P）选token，选中的token拼回输入继续预测下一个，知道遇见EOS停止符。

### 9、解码策略对比：贪心解码 vs Beam Search vs 采样
    解码策略主要分贪心、Beam Search 和采样三类。贪心最快但易重复；Beam 保留多条路径全局较优，适合翻译摘要；采样引入随机性更自然，适合对话创作。实际工程里问答和代码生成我用贪心+T=0，对话用采样+T=0.7

### 10、为什么 Temperature=0 时输出依然不完全确定？
    Temperature=0 能大幅降低随机性，但不保证 100% 确定，因为 GPU 浮点运算的并行累加顺序有微小差异，极端情况下会影响 argmax 结果。要做到严格可复现，需要固定 seed、关闭采样随机并保证推理环境一致


### 11、什么是重复惩罚？如何防止复读机
    复读机是解码阶段常见的问题，我用repetition_penalty对已经出现的token的logits做惩罚，一般设1.1 ~ 1.2兼顾流畅和多样，在配合no_repeat_ngram和惩罚频率，效果更好。

### 12、什么是停止符？
    生成终止有三层保险：模型预测出 EOS 自然结束、max_tokens 硬性截断兜底、Stop Words 按业务边界提前终止。工程上我必设 max_tokens 防成本失控，流式场景识别到 EOS 就立即断开连接。

### 13、Embedding(嵌入向量)是什么？和token是什么关系？
    Embedding 是把 Token 映射成稠密向量的过程，语义相近的文本向量距离就近。重点要区分静态 Embedding 和上下文 Embedding——现在的 LLM 都是上下文相关的。
    在 RAG 里它是检索的基石：文档和问题向量化后用余弦相似度匹配，这也是我们系统召回率的基础。

### 14、In-Context Learning(上下文学习ICL)？Zero-shot/Few-shot 区别？
    ICL是不改参数的学习--通过Few-shot示例让模型掌握任务，它和微调的本质区别是：ICL走前向计算，微调走反向传播。ICL说是底层Attention+MLP隐式形成的低秩更新，效果等效于一次隐式微调。
    在生产过程中，我通常用ICL快速验证任务可行性，验证通过后在决定要不要微调优化。

### 15、LLM 是怎么训练出来的？预训练 → SFT → 对齐（RLHF/DPO）三阶段流程
    LLM训练是预训练 -> SFT -> 对齐 三阶段流水线：预训练在TB级数据上学next-token预测，得到博学的base模型；SFT用高质量指令对教会它对话和遵循指令，最后用RLHF/DPO做偏好对齐，决定模型的安全边界和价值观。
    三阶段数据量级递增。这也是为什么对齐数据最贵。做应用开发时，理解这点非常重要，rag解决知识不足，微调解决能力不足，对齐解决行为不合规。

### 16、什么是 Scaling Law（规模定律）？Chinchilla 法则修正了什么？
    scaling law说模型效果和参数量、数据量、算力呈幂等关系，可以预测，结论就是：模型越大、数据越多，效果越好，且可预测
    chinchilla修正了只堆参的误区，提出参数和数据1：20配比--70B模型要喂1.4Ttokens才最优。工程上它的价值式可预测性的：现在1B小模型做实验，再推算70B的表现，
    节省大量试错成本。2026年scaling已经从训练侧延申到推理侧，就是test-time compute。

### 17、KV缓存是什么，为什么能大幅加速LLM推理？
    KV Cache = 把已经算过的历史 Token 的 K（Key）和 V（Value）缓存起来，避免重复计算。
    答：KV Cache是LLM推理加速最基础的优化，自回归生成时历史token的K、V不会变，缓存后只需要计算新的token的Q/K/V,复杂度从 O(n²) 降到 O(n)，代价就是显存。
        ----所以长上下文场景要配合 PagedAttention 和 KV 量化。我的项目里多轮对话场景靠它把单 token 生成延迟降了一个数量级。

### 18、RLHF 和 DPO 有什么区别
    - **RLHF**：训练一个奖励模型打分，再用强化学习（PPO）优化策略
    - **DPO**：跳过奖励模型，直接在偏好数据上优化，数学上等价于 RLHF 的最优解
    答：RLHF和DPO目标一致但路径不同：RLHF先训奖励模型早用PPO优化，需要维护4个模型、训练不稳定，但灵活；DPO直接对偏好对构造损失，数学上等价于RLHF的最优解，简单稳定，
        是当前主流。选型上：资源有限用DPO，追求极致用RLHF，可验证任务考虑GRPO。微调项目就是用DPO做对齐，一周就能收敛


### 19、7B模型需要多少显存？参数量如何换显存？
    核心公式：显存（GB）≈ 参数量 × 每参数字节数
    训练峰值 ≈ 权重 + 梯度、优化器状态 + 激活值 + 临时空间与其他开销

    答：显存估算的核心是参数 * 字节数：7B模型精度FP16推理要14GB，INT4只需要3.5GB，但全参训练要16字节/参数，7B就要112GB，所以训练必须上lora--只训0.1%的参数，24GB就能微调7B。
        如果14G微调时显存超了，还要考虑KV cache和激活值。


### 20、什么是MOE？为什么大量LLM都用它？
    MoE（Mixture of Experts）= 把 Transformer 中的 FFN 层替换成"多个专家 + 路由器"，每个 Token 只激活少数几个专家
    核心原理：
    传统 Dense 模型：
        输入 → FFN（所有参数都计算）→ 输出

    MoE 模型：
        输入 → 路由器(Gating) → 选 Top-2 专家 → 只有选中专家参与计算 → 加权求和输出
            └─ 专家1(FFN-A) 专家2(FFN-B) ... 专家8(FFN-H)
    流程：1、路由器打分：为每个token计算出专家的选择概率。2、选top-K专家：一般K=2. 3、加权融合：选中专家的输出* 门控概率 再相加
    优势：1、容量大，知识多 2、计算省，推理快 3、扩展性好  
    劣势：1、显存占用高。 2、通信开销：专家并行时 Token 要跨卡转发 3、负载不均衡：热门专家被反复选中。4、微调更脆弱。


### 21、为什么说 LLM API 是无状态的？多轮对话的"记忆"到底存在哪？
    模型推理本身不会凭空记住上一轮；当前输出只能依赖本次实际提供或由平台关联进来的上下文。计算层可以无状态扩展，但会话隔离、持久化、重试幂等和工具副作用仍必须由系统显式治理
    无状态的优势：1、便于水平扩展， 计算节点可以保持无状态，会话状态放到数据库或平台会话层  2、状态可治理：历史、摘要和长期记忆可以独立做权限、保留期限和删除
        3、但不天然幂等：采样、并行计算和工具副作用都可能导致重试结果不同；涉及写操作时必须使用幂等键、去重和事务保护

### 22、什么是 Prompt Caching（提示词缓存）？怎样评估它能否真正降本？（API 层高频）
    API 层复用相同"前缀"的 KV Cache，跳过重复的 Prefill 计算。
    同一个前缀（system prompt + 固定文档）第一次计算后，K/V缓存保留一段时间，后续请求只要前缀字节相同，直接服用缓存，只计算新增部分。
    答：prompt cache复用重复前缀的计算，在生产中要把稳定内容放前、动态字段放后，并通过缓存命中token、首token延迟（TTFT）以及账单验证收益；最佳实践中我们项目中固定在system系统提示词中的。


### 23、为什么LLM数学能力差，怎么缓解？
    原因：1、tokenization不一致，数字被切碎且不稳定，1234 → ["12","34"]--模型看不到稳定的"数位"结构，难以学算术规律
        2、自回归误差累积：多步计算中间错一步，就步步错  3、训练目标不匹配，next-token预测的是文本统计分布，数学是精确符号计算。
        4、缺外部工具，模型没有计算器，预算都是通过神经网络处理
    缓解：1、通过COT分布计算，一步步验证 2、代码解释器/工具调用，让大模型通过python代码进行验证。3、约束解码，数字场景通过格式化输出并校验。
        4、专用数学模型，数学题给到推理模型。

### 24、 Transformer 中的 Attention 机制是什么？为什么它是 LLM 的核心？（不属于agent开发，了解即可）
    **Attention = 让模型在处理每个 Token 时，动态关注输入中所有其他 Token 的相关程度。**
    公式：Attention(Q, K, V) = softmax(Q · K^T / √d_k) · V
    答：Attention 的核心思想是'让每个词都能看到并关注其他所有词'。公式上就是 Q·K^T 算相似度，Softmax 归一化，再加权求和 V。Multi-Head 相当于多个专家各看一个角度，
        最后拼接起来。它是 Transformer 取代 RNN 的关键——RNN 只能串行序列化地看前面，Attention 可以一次性全局关注，既快又准。

### 25、为什么 Transformer 需要 Position Encoding？RoPE 和绝对位置编码有什么区别？ （不属于agent开发，了解即可）
    Self-Attention 本质是对称操作，无法区分'猫追狗'和'狗追猫'的顺序差异，所以必须加位置编码。RoPE 是目前最主流的方案——它通过旋转矩阵把位置信息嵌入到 Q/K 向量中，
    好处是点积自动变成相对位置依赖，还支持长度外推。现在主流的 LLaMA、Qwen、DeepSeek 都用 RoPE。如果需要比训练更长的上下文，可以用 YaRN 这类扩展方法。
    

### 26、LLM 预训练用什么损失函数？Cross-Entropy Loss 和 Perplexity 有什么关系？
    LLM预训练用的是标准交叉熵损失（Cross-Entropy Loss）：负对数似然。本质上就是测模型对正确token给了多高的概率。Perplexity是交叉熵的指数形式，可以理解为
        模型每次做选择有多少个同样可能的选项--PPL越低越确定。训练中我主要看两条曲线：Train Loss 和 Validation Loss，如果后者开始回升那就是过拟合了。


### 27、什么是 Catastrophic Forgetting（灾难性遗忘）？微调时怎么缓解？
    灾难性遗忘的本质是模型为了适应新数据而覆盖了旧权重。我的应对三板斧：1）微调时混入 5-10% 的通用预训练数据；2）尽量用 LoRA 而不是全量微调，冻结大部分权重天然防遗忘；
        3）调完后立刻用 MMLU 或 GSM8K 跑一下，确认通用能力没有崩。一般这样组合用，遗忘程度能控制在可接受范围内


### 28、什么是 Function Calling（函数调用）？它是如何工作的？为什么重要？
    **Function Calling = 让 LLM 输出结构化的 JSON 来描述"调用哪个函数、带什么参数"**，从而打通大模型与现实世界的操作接口。
    答：Function calling 是让模型从聊天机器人变成智能体的关键桥接技术。从声明工具schema --> 模型判断是否调用 --> 生成结构化json --> 应用执行 
        --> 结果回传 --> 综合回答。 核心优势是不需要微调模型就能扩展功能。但工程不少坑：参数类型漂移、无限循环、权限控制，所以在开发过程中要时刻注意做对应schema约束，调用工具的上限以及降级策略。


### 29、什么是思维链推理（Chain-of-Thought, CoT）？为什么它能大幅提升模型表现？
    CoT的本质是引导模型把隐式推理变为显式推理。就像让学生做题不能只写答案，要写解题步骤一样。工业界应用时，我的经验是：复杂任务用CoT提30-50%准确率，
        但要注意token成本和幻觉传递风险。对于关键决策，我会结合Self-Consistency策略——让模型多跑几次CoT取多数投票结果

### 30、 什么是PEFT（参数高效微调）？LoRA/QLoRA/P-Tuning有什么区别？
    PEFT的关键洞察是：预训练模型已经学会了通用语言能力，适配新任务只需要微调一小部分参数。LoRA通过低秩分解来实现这个目标--冻结全量权重，只训练两个小矩阵的乘积。在生产环境中，
        我用QloRa在单卡调出媲美全量微调的效果，显存从14GB压到12GB以下。

### 31、 少样本学习（Few-Shot Learning）的最佳实践是什么？什么时候用ICL替代微调？
    "我的原则是：能用ICL解决的就不微调，因为迭代成本低得多。具体做法是精心挑选3-5个代表性的正向例子放在prompt最后，确保输出格式严格对齐。
        但当任务对一致性要求很高（比如金融风控），或者需要长期稳定的表现时，我会用LoRA做轻量微调——两者结合才是生产环境的最优解。

### 32、 幻觉有哪些不同类型？如何在工程中系统性地检测和处理？
    类型：1、事实性幻觉，编造不存在的事实。2、来源幻觉：虚构不存在的引用来源。3、逻辑幻觉：推理链条中的中间步骤出错。4、过度自信：在不确定是表现非常肯定。
        5、上下文错位：在多文档QA中引用错误文档。4、指令遵循失败：忽略prompt中的约束。
    解决方案：五层防御体系：从Prompt约束开始，到RAG溯源，再到工具校验、规则引擎，最后是人审兜底。实际生产环境中根据真实场景来设定，如客服这种场景是可以接收1%的轻微幻觉，
        高精度场景则必须控制在0.01%以下。这种系统中记录日志库，记录所有被拦截案例，持续改进。


### 33、prompt设计最佳实践
    1、明确角色  2、清晰任务  3、提供实例 4、指定格式  5、设定约束

### 34、什么是 Prompt Injection（提示词注入）？和 Prompt Leakage 有什么区别？s
    **Prompt Injection = 攻击者把恶意指令"注入"到模型输入中，让模型执行攻击者意图**
    答：prompt injection是让模型执行攻击者的指令，和leakage偷提示词不同。最危险的是间接注入--恶意指令藏在rag的检索网页中，用户一问就触发。
        我们系统防御包含4层：角色系统隔离，指令边界声明，输入关键词检测，工具权限最小化。核心原则就是所有外部输入都当作不可信数据处理。


### 35、Structured Outputs / JSON Mode 是什么？和 Function Calling 有什么区别？
    答：json mode 本质约束输出为合法json，只保证json合法，适合通用json输出。structured outputs本质是约束json符合schema，严格校验字段类型，适合严格业务结构。
        function calling就是让模型调用工具，但真正执行动作的是应用。Schema 合法不等于业务安全，设计金额等高风险动作还必须做鉴权、金额/对象校验、幂等、审批和审计

### 36、 ReAct Prompting 的局限是什么？工程实践中如何规避？
    ReAct 的常见风险是上下文膨胀、循环、错误观察传播和逐步调用延迟。可以用结构化状态、步骤/预算上限、工具结果校验和可更新计划治理；
        只有互不依赖且无冲突的动作才并行。摘要也可能丢信息，因此要保留关键事实来源，并用任务集比较成功率、成本与尾延迟。


### 37、 如何写 System Prompt 让 Agent 更稳定？必须包含哪些要素？
    **生产级 System Prompt 的 8 个必需要素：**
    1、角色定义：明确agent是谁，能做什么不能做什么  2、核心能力边界：可用工具列表，权限范围 3、输出格式约束 -> JSON/纯文本/分段落，错误处理格式
    4、安全与合格规则 -> 禁止行为、敏感信息处理、合规要求 5、决策逻辑规则：遇到不确定的处理方式 6、上下文管理策略：历史信息如何使用、多轮对话如何组织
    7、错误处理与恢复：工具调用失败、超时如何处理 8、示例注入
    
    Agent System Prompt 通常要说明目标、边界、可用工具、输出契约、异常处理和停止条件，但不存在固定八要素。安全和权限不能只靠提示词，必须由应用层策略执行；失败次数、转人工阈值和预算应从业务风险及评测数据校准

### 38、Prompt Caching（提示词缓存）是什么？如何判断它是否真的省钱？
    prompt caching适合长期重复的稳定前缀，例如工具定义、固定规则和共享文档。优化时将稳定内容放到前面、动态内容放后面，再从api usage中统计写入与命中token。不能只看命中率，还要把缓存写入费、TTL内复用
        次数和延迟一起计算。


### 39、Chain-of-Verification (CoVe) 是什么？如何减少 LLM 幻觉？
    CoVe = 让模型先写草稿，再自己出验证题，验证后再重写，形成闭环
    它增加了调用次数和延迟，而且模型自证不等于外部事实核验。高风险场景应把验证问题交给检索、数据库或规则工具，并在自己的评测集上比较事实性、拒答率、延迟和成本

### 40、生产环境中如何 A/B 测试和评估不同的 Prompt？
    **Prompt 不是写完就好的——它像代码一样需要版本管理、回归测试和生产灰度**
    1、离线回归测试，每次改prompt跑一边黄金测试集。 2、线上影子测试，新旧两个prompt同时运行，旧的给用户，新的记录不输出。收集到真实反馈后在比较。
    3、在线A/B测试，按流量百分比分流不同版本，监控业务指标（满意度、转化率），统计显著后全面切换
    工具选择：langsmith、ragas


### 41、Prompt Safety Guardrails 和生产级防护体系是什么？
    System Prompt 只能做「第一道防线」，生产级安全必须有多层护体系。
    答：安全不是提示词的属性，而是系统的属性。system prompt只能做软边界，真正的要独立于llm的检测层。包括输入意图分类，输出评分、PLL检测。我们生产环境在输入输出
        使用meta开源工具 Llama Guard，在输入时检测，输出审查、最后人工复核保证三层安全保障。

### 42、如何判断一个问题该用 Prompt Tuning、Retrieval、Tool Calling 还是 Fine-tuning 来解决？
    需要看具体的生产场景，微调不是万能药。
    1、 Retrieval（检索增强），适合场景：**知识缺失型问题**  2、 Tool Calling / Function Calling（工具调用），适合场景：能力缺失型问题
    3、Workflow / Prompt Chaining（工作流编排）,适合场景：**流程复杂型问题**
    4、Fine-tuning（微调），适合场景：**模式固化型问题**
        Fine-tuning 的局限性：01、不解决知识问题 02、每次模型升级需重新训练 03、数据门槛高 04、迭代周期长 05、不适合在线调整

    Fine-tuning 适合格式统一、语气一致、分类稳定的场景。如果你的问题是'模型不懂我们公司的内部政策'，答案是 Retrievale —— 给模型看政策文档就行，不用微调。
    如果你在犹豫要不要微调，说明你需要更多数据，或者问题其实可以用更好的 Prompt + RAG 解决

### 43、多个工具并行调用时，如何处理依赖关系、超时控制和异常熔断？
    并行工具调用的难点不是并发本身，而是三个工程问题：1、依赖关系--先确定那些可以并行，那些必须等待上游完成，避免时许问题； 2、超时控制--每个工具都必须有个熔断策略，
        如果工具调用超过多少秒，直接返回结构化错误信息，不能让工具失败影响整个对话。3、异常熔断-->当工具调用连续失败时自动熔断，防止一直调用死循环，可以考虑降级调用非实时接口或人工介入。
    生产环境每一层调用的时候都需要加上对应保障以此保证容错能力

### 44、LangGraph 和 LangChain 的核心区别是什么？什么时候应该用哪个？
    本质区别：流水线思维 vs 状态机思维
    答：本质上解决的是不同层次的问题。langchain是一个高层抽象库，帮你快速拼装chain、agent、memory等组件。langchain是线性的，遇到需要循环，条件分支，状态等复杂场景就比较笨拙。
        langgraph是把整个流程看做有向图，有节点、边、状态等核心来达到复杂场景的处理。特别是业务多agent系统中，langgraph是主流使用。

### 45、如何量化评估一个 AI Agent 的整体性能？
    分三层：1、端到端的业务指标：如任务最终完成比例，用户发起请求到总体结束的时间、无需人工介入一次完成比率、用户评分、每个任务完成的成本。
        2、过程指标：01、规划质量（完成任务的步骤是否为最优路径） 02、记忆有效性（召回历史信息相关信息比例） 03、工具调用质量（工具调用成功率） 04、安全性（幻觉比例，安全拦截次数）
        3、效率指标：完成任务总token数、平均api调用次数、系统能处理的请求数
    追问1：如何定义任务成功？答：取决于具体业务场景，如客服场景用户提问已经被满足就算完成。数据分析场景就是看最终给出的结论是否跟系统或人工最终计算出来一致。目的就是看是否与业务达到最终一致性。
    追问2：怎么检测死循环？ 答：设置对应最大推理步数，超过就强制中止，之前8月份准备优化为根据状态签名检测重复，用hash算每个节点状态值，如果出现相同状态则进入死循环。

### 46、什么是 Model Routing（模型路由）？如何根据任务复杂度选择不同档位的模型来控制成本？
    Model Routing = 根据每个请求的难度，动态路由到最合适的模型档位。
    总共应该是三种策略：01、基于规则硬路由 02、轻量分类器路由（推荐） 03、多阶段升级路由
    答：我们项目中在网关层级加了一点规则的硬路由，比如像一些总结、翻译、问候这些简单的规则都是直接下发到简单模型，然后在业务网关层使用轻量分类器路由，通过小模型快速判断该任务需要使用的模型，
        然后还需要加上监控，看一下如果路由到便宜模型后用户体验率，然后再看最终的成本，走到便宜模型和旗舰模型的最终费用。
