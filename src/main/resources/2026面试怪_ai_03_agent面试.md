# agent面试题


### 1、ReAct 模式是什么？完整流程是什么？
    ReAct = Reasoning + Acting（推理 + 行动）
    1. Thought（思考）：分析当前情况，决定下一步
    2. Action（行动）：调用工具（搜索、API、数据库等）
    3. Observation（观察）：获取工具返回结果
    4. 循环 1-3，直到任务完成
    5. Final Answer（最终答案）

### 2、 Function Calling 的原理是什么？
    让 LLM 调用外部函数。本质是将非结构化的自然语言转化为结构化的 JSON。在实战中，我通过它实现了自然语言直接查询 SQL 数据库，极大地降低了非技术人员的使用门槛


### 3、如何防止 Agent 进入死循环？
    死循环原因：1、工具调用失败，agent重复尝试。2、任务太复杂，agent无法完成 3、prompt设计不好，agent理解错误。
    防护措施：1、最大轮次限制（最后10伦） 2、超时机制（超60s后停止） 3、工具调用去重 4、反思机制 5、人工介入

### 4、多 Agent 协作怎么设计？
    整体供应链agent中包括采购寻源协同agent、食品安全agent、主数据agent。从新品引入到原料配比、以及证件核验的agent系统。

### 5、你设计过哪些类型的 Agent？
    基于供应商协同agent: 可以理解为供应商在接入协同前后的问答操作系统，在供应商意向合作界面时可进行问答以及合作意向。
    在供应商入驻后，可通过问答获取订货通知单、合同、证件等相关问题，以及报表。
    食安、主数据agent：在供应链系统中，提供食品安全证件自校验，订单证件原料物料bom信息质量合规。并且在主数据新品引入、供应商引入等模块分析可接入商品，参与自动审核，自动下单，智能补货


### 6、Agent 的 Memory 怎么设计？
    短期记忆 和 长期记忆
    短期记忆：1、存储最近N轮对话 2、用列表或环形缓冲区 3、超出限制时总结或截断
    长期记忆：1、存储重要信息到向量数据库 2、按需检索相关记忆 3、支持遗忘机制，删除历史记忆

注意：1、谈agent时不要只说agent会调用工具，要这样说：我认为agent的核心在于闭环。模型生成答案后，我会设计一个review节点让它自我检查，这个答案是否满足用户需求？如果不满足则重新执行。这种反思机制可提升agent的可靠性。
    2、谈function calling时不要说只调用外部api，要这样说：function calling的本质是将非结构化的自然语言转换为结构化json。比如通过自然语言直接查询sql数据库，降低非技术人员使用门槛。同时加入鉴权机制和黑白名单保证安全性。

### 7、什么是LangGraph?如何构建复杂Agent工作流?
    用图结构构建有状态的Agent应用
    LangGraph解决了LangChain的痛点:不支持循环和复杂分支。我们系统是用LangGraph构建了多Agent,支持多轮迭代优化,从开始到结束,循环直到质量达标。,比纯Prompt灵活。

### 8、工具调用的完整流程，如何处理失败？
    工具调用流程，识别->参数提取 -> 执行 -> 结果处理

### 9、工具调用失败如何处理？充实策略是什么？
    工具调用失败分三类处理：1、参数错误（这种可以让llm重试，或手动更正）、
    2、因调用方突然服务问题导致api瞬时调用错误，然后在某一时间恢复，可能多agent因为积压的请求可能会导致瞬间打死，这种解决方案加入重试时间，抖动请求，比如协同agent实在0.3s内进行重试，食安agent可以在1.5s后进行重试。把请求分散到0~2秒内随机。
    3、然后对于如果重试5次之后，仍然失败，则进行熔断。在配合half-open半打开试探机制，进行重连服务，从而保护后端服务。

### 10、Agent 的短期、长期与工作记忆如何实现读写、检索和遗忘？
    记忆系统 = agent的大脑存储，决定能否长期陪伴用户。
    短期记忆设计: 1、滑动窗口 2、 分层管理(推荐⭐)：比如三轮对话内保留完整对话记录，历史的对话进行摘要处理。
    长期记忆设计：1、向量数据库，存用户偏好和事实，用LLM判断重要性决定是否存储。检索时混合向量+元数据过滤，避免无关记忆。

### 11、 Agent 如何做规划（Planning）？任务分解策略是什么？
    把大任务分解成可执行的小步骤
    Agent规划我用Plan-and-Execute,先用LLM制定完整计划,再逐步执行并根据结果调整。复杂任务用Tree of Thoughts探索多路径,每层生成3个候选思路,评分选最优。工具调用多时用ReWOO预规划+批量并行,比ReAct快40%。关键是要能动态调整计划,而不是死板执行。

### 12、单轮对话和多轮对话的 Token 消耗大概多少？如何控制？
    单轮对话 Token 消耗约 1K-4K，多轮不控制会线性增长爆成本。我的策略是三层：最近3轮保原文保障连贯性，历史部分用小模型摘要（节省80%成本），RAG 召回内容做相关性过滤只保留 top-k chunk。实测10轮对话 Token 消耗控制在 2K 以内，单次成本 < ¥0.01。
